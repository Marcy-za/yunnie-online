Privacy policy

Khadgar, a personal assistant by Marc Yunnie · yunnie.online · Last updated 22 October 2026

What Khadgar is

Khadgar is a private, single-user assistant that I run on my own server. It has one user, me. It is not offered to the public, and nobody else signs in to it.

Google data it accesses

Khadgar signs in to one Google account, a mailbox created for the assistant (khadgar.email@gmail.com), through Google's OAuth. It asks for:

  • Gmail, read-only (gmail.readonly): to read messages sent to that mailbox, such as forwarded job emails and calendar invitations. It cannot send, delete, label or change any mail.
  • Google Calendar events: to add events to the assistant's own calendar after I approve them.

How the data is used

Messages are used only to find job-search updates and to suggest calendar events, which I confirm before anything is created. The text of a message may be sent to an AI model provider (Anthropic) to produce those suggestions. That provider is used as a processor and does not receive the data for any other purpose.

The data is not used for advertising, is not sold, and is not shared with third parties. It is not used to develop or train generalised AI models.

Where it is stored and for how long

Everything Khadgar stores stays on my own server at home. Message bodies are read in memory and are not saved. For job emails it keeps only the role details (title, company, place, workload) for 45 days. For calendar suggestions it keeps the suggested event and the sender and subject of the email it came from, until I dismiss it or it falls outside the latest 300 suggestions. Message text is sent to an AI model provider (Anthropic) only to produce those suggestions. Access tokens are kept in a private configuration file on that server. I can revoke Khadgar's access whenever I want at myaccount.google.com/permissions.

Google API Services User Data Policy

Khadgar's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.
